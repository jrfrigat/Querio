# История изменений

Здесь фиксируются все заметные изменения Querio. Формат следует
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии - [семантическому
версионированию](https://semver.org/lang/ru/). Пока проект на 0.x ломающее изменение - это подъём
минорной версии, никогда не патча.

Версия берётся из тега git: MinVer читает `vX.Y.Z` и пакует именно её. Тег и есть релиз.

## [0.0.1] - 2026-08-03

Первый публичный выпуск. Модель и все цели готовы и покрыты тестами; версия остаётся 0.x, потому что
сериализованная форма `QuerySpec` ещё не прошла проверку настоящим потребителем, а сохранённый
запрос - контракт, который лучше менять, пока это дёшево.

### Добавлено

**`Querio`** - ядро.
- `QuerySchema`: сущности, поля, внешние ключи и объявленные функции (значения и табличные), где
  логические имена отделены от физических, чтобы запрос пережил переименование.
- `QuerySpec`: сериализуемый запрос - источники, соединения с обязательными псевдонимами, агрегаты
  включая перцентили, группировка с усечением дат, фильтр групп, сортировка, постраничность.
- `QueryBuilder`: fluent-сборка запроса.
- `QueryValidator`: проверка без привязки к диалекту. Соединение может цепляться только к участнику,
  объявленному раньше него, поэтому саморефлексивная связь не может поручиться сама за себя.
- `QueryChoices`: что можно дать запросу следующим - поля, соединения, операторы, агрегаты, цели
  сортировки, - сужено через `IQueryCapabilities`, чтобы не предлагалось то, что упадёт при
  отрисовке.
- `QueryRenderer<TExpression>`: общий обход, через который рендерится каждая цель; `TExpression`
  оставлен открытым, чтобы цель вообще не обязана была порождать текст.
- `QueryFeature` / `IQueryCapabilities` / `QueryRenderException`: цель объявляет, чего не умеет, и
  падает громко вместо приближения.

**`Querio.Sql`** - параметризованный SQL для SQL Server, PostgreSQL и SQLite. Каждый диалект
объявляет свои пределы: у SQLite нет перцентиля, SQL Server отказывается от сгруппированного, а не
притворяется. Имена экранируются, шаблоны LIKE экранируются, ни одно значение не вклеивается в текст.

**`Querio.OneC`** - язык запросов 1С. Кириллические ключевые слова, параметры `&p0`, и
идентификаторы отвергаются, а не экранируются, потому что 1С не умеет заключать имя в кавычки.

**`Querio.Linq`** - настоящие деревья выражений. `QueryPredicate.For<T>` отдаёт EF Core то, что тот
умеет транслировать; `QueryExecutor.Execute` выполняет весь запрос по объектам. Правое и полное
внешние соединения объявлены неподдерживаемыми, а не приближены.

**`Querio.Http`** - строка запроса, в обе стороны. Обратимость точная, поэтому запрос переживает
ссылку, закладку или обращение клиента.

**`Querio.Text`** - запрос как фраза, в обе стороны, со сменными связками, чтобы описание писалось и
читалось обратно на другом языке.

**`Querio.Language`** - SQL-образный текст с навигацией по внешним ключам
(`[r].[apiKeyId].[ownerId].[name]`), чего не умеет никакой SQL. Сообщает каждую проблему с точным
местом, а не останавливается на первой, и возвращает частичный запрос рядом - чтобы редактор
оставался полезным, пока текст ещё неверен. `QueryCompletion` отвечает, что можно набрать дальше.

### Примечания

- Ни один поставляемый пакет не тянет стороннюю зависимость; это проверяется тестом для каждого.
- Целевые платформы: `netstandard2.0`, `net8.0`, `net9.0`, `net10.0`.
- Сборка везёт дескриптор ILLink: типы спецификации - позиционные записи, и публикация с триммингом
  иначе срезала бы имена параметров конструктора, по которым сопоставляет сериализатор, а
  сохранённый запрос перестал бы читаться - отказ, который проявляется только в Release-публикации.
