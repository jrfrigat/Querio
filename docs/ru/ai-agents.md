# Работа с ИИ-агентами

Querio хорошо подходит для того, чтобы запросы строила модель, по одной причине: **модель никогда не
пишет текст запроса**. Она выбирает из закрытого набора вариантов, а на выходе получается объект,
который кто-то другой проверяет и отрисовывает. Внедряться просто некуда - нет строки.

## Схема, которая работает

Не просите у модели SQL. Просите выбирать по шагам из того, что `QueryChoices` объявляет доступным.

```csharp
var choices = QueryChoices.For(spec, schema, SqlServerDialect.Instance);

choices.Fields;                 // что можно вывести
choices.Joins;                  // что можно присоединить и по какой связи
choices.OperatorsFor(field);    // сужено до того, что цель умеет
choices.ValueKindsFor(field);   // литерал, множество, другое поле, относительный момент, вызов функции
choices.SortTargets;
```

Каждый список уже сужен и схемой, *и* целью, поэтому модель не может выбрать то, что упадёт позже.
Каждый оператор к тому же сообщает свою `QueryValueArity` - `None`, `One`, `Two`, `List`, - так что
описание инструмента знает, сколько значений спрашивать, и это знание нигде не зашито.

## Как описание инструмента

`QueryChoices` ложится на параметры инструмента напрямую:

```csharp
// перечисление того, что можно вывести прямо сейчас
var fields = choices.Fields.Select(f => f.ToString());          // "r.route", "r.timestamp", ...

// перечисление операторов, допустимых для поля, которое модель только что выбрала
var operators = choices.OperatorsFor(field).Select(o => o.Operator.ToString());
```

Перегенерируйте схему инструмента после каждого шага - и модель выбирает из меню, корректного по
построению. Это стоит больше, чем любые уговоры в промпте про то, какие колонки существуют.

## Если модель пишет текст

Хотите, чтобы модель писала на языке запросов, - читайте результат через `QueryLanguage.Read` и
возвращайте ей диагностики:

```csharp
var result = QueryLanguage.Read(modelOutput, schema);
if (!result.IsValid)
{
    // Все проблемы сразу, каждая с точным участком, - гораздо лучший корректирующий промпт,
    // чем «синтаксическая ошибка около строки 3».
    var report = string.Join("\n", result.Diagnostics.Select(d =>
        $"{d.Message} (at {d.Start}..{d.End})"));
}
```

Читатель намеренно возвращает все ошибки, а не первую, и вместе с ними частичный запрос, поэтому
одного круга исправлений обычно достаточно.

## Показать запрос на утверждение

Прежде чем выполнять то, что сочинила модель, покажите это человеку словами:

```csharp
QueryDescriber.Describe(spec, schema);
// From Requests (r), showing Route and the number of rows called total,
// where (Timestamp is at least the last 30 days and Error is "true"), grouped by Route, first 20
```

Описание использует подписи из схемы, а не имена хранилища, поэтому читается так, как человек думает
о своих данных. Оно ещё и читается обратно, так что шаг подтверждения может восстановить ровно тот
запрос, который был показан.

## Что Querio не решает

**Авторизацию.** Querio отрисовывает то, что говорит схема. Какие сущности и поля доступны конкретному
пользователю - или конкретному агенту - решает приложение, и естественное место это применить - схема,
которую вы передаёте в `QueryChoices`: соберите суженную `QuerySchema` под вызывающего, и варианты
сузятся вместе с ней.

**Выполнение.** Querio не открывает соединений. Тайм-ауты, ограничения на число строк и учётные
данные - забота того, кто выполняет SQL. Модель, выбирающая запрос, - это не модель, трогающая базу.
